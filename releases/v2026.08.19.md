## ☁ APP Server (Cloud Side)
> Deployed: 19-08-2026 17:53:13 IST | Previous: 18-08-2026 17:28 IST

- Implemented a 10-minute time-gap condition in the GrayQuest webhook processing logic for direct payments to prevent race conditions with the ongoing PG_Response process. Previously, the webhook could trigger while the user was actively being redirected to the success page, causing the webhook to prematurely interact with the fee update logic while the transaction was still marked as pending. By comparing the transaction creation time (TxnDt) against the current time, the webhook will now safely ignore and return a success response for any transaction less than 10 minutes old. This ensures the standard browser-based PG_Response has exclusive priority to process the receipt generation without interference, while gracefully relying on the existing cron fallback to capture any edge cases where the user drops off before completion. The auto-debit workflow remains completely isolated and unaffected by this timing check.
